# Mission — Campus2Corporate Hackathon Briefing

## Why this matters

I'm preparing for the **MP Online Innovate hackathon** (https://innovate.mponline.gov.in/) with a project called **Campus2Corporate** — an AI career-readiness app for Tier-2/3 Indian college students. I want to:

1. **Know the project cold** — what it does, how it's built, why each piece exists
2. **Anticipate judge questions** — so I can defend every design choice in the 3-min pitch and Q&A
3. **Get actionable improvements** — what to add, cut, or polish before submission to stand out from ~hundreds of competing teams
4. **Have everything in a dark-themed reference** I can review the night before the demo

## What "done" looks like

- I can answer any judge question about the rubric, privacy claim, offline mode, role architecture, or failure modes
- I have a punchy 3-min demo script and a list of "if asked X, say Y" responses
- I have a prioritised backlog of improvements split into **must-do before submission** vs **nice-to-have if time**
- A printable dark-themed cheat-sheet I can read in 10 minutes

## Constraints

- Hackathon context: short time, must work on stage (Wi-Fi flaky), judge panels are non-technical-heavy + some technical
- Submission platform: MP Online Innovate portal (govt hackathon → judges value **social impact**, **scalability**, **data privacy**, **public-good angle**)
- Stack is locked: Vite + React + Tailwind v4 + Supabase (planned) + Gemini Flash

## Tone preference

- Direct, no fluff
- Cite the source file/line when making a claim about the code
- Recommendations should be **ranked**, not a flat list
